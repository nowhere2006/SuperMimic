## 当前仍存在的风险

### MuJoCo solver 迭代上限提示

若干短程 CPU 运行出现 `solver iterations limit reached` 或 line-search 上限提示。较早初始闭环 profile 曾将 line-search 上限从 20 提至 50，最终该次运行不再提示；但 2026-10-27 的后续运行仍有 solver 迭代上限提示，solver iterations 保持 10，未隐藏警告或改写求解器配置。

已检查的 loss、梯度和解析对拍有限，不能证明每个接触步都充分收敛，也不能排除求解误差影响世界模型监督标签。长时运行应统计警告频率并观察相关转移；当前没有据此宣称接触模拟已完全收敛。

### 分组损失仍是待观察的工程适配

当前默认采用六组几何 L1 状态误差，按首次真实窗口误差确定固定尺度，使各项初始贡献接近；SuperMimic 论文没有公开规定这套分组和自动尺度。贡献相等不意味着参数梯度平衡，也没有证据证明该适配改善策略表现。原始 MSE 基线仍可用于后续受控对照；L1 与 MSE 的 loss 数值不可直接比较。

### 回报采样与截断估值尚未充分验证

当前回报 bin 使用 EMA 和历史 softmax 权重等工程估计细节。回报 bin 以实际回合后缀统计；时间上限截断时不做 bootstrap，可能使尾部回报估计偏低。正式协议前需结合论文表述和目标实验明确处理方式，不应把当前采样器细节视为作者唯一实现。

### 训练恢复不是仿真现场精确恢复

完整迭代 checkpoint 可恢复模型权重、Adam 状态、采样器、调度进度及保存的随机状态，并重建仿真环境、重置并预热 replay。它不保存完整 MuJoCo 接触/求解器内部状态、在途 episode 和原 replay 的完整现场，因此属于 warm restart/继续训练，不是从中断时刻逐步确定性续跑。中断 emergency 快照只供诊断，不能替代最后一个完整迭代 checkpoint 续训。旧 format、旧动作语义、不同 manifest 或不同损失配置会被拒绝自动混用。

### 记录不能恢复所有事后分析

运行记录保存逐轮指标、转移、有限的 detached rollout probe 和 checkpoint。它不保存完整 autograd 图、每阶段全部参数梯度、所有优化中间权重或接触力，因而不能事后精确重算每次 BPTT 梯度，也不能从摘要恢复未落盘的信息。JSONL 逐条 flush，转移分块落盘；突然终止仍可能损失最后尚未 flush 的块，kill -9 或断电尤其如此。

## 尚未验证的事项

- 没有完成 SuperMimic 学习效果实验：短跑回报、有限非零梯度、loss 变化都不能证明策略学会动作或达到论文水平。
- 没有验证 CUDA/NVIDIA 训练路径、租用 GPU、正式并行环境数、全规模吞吐或 320k 迭代训练。
- 尚无正式 train/validation/test 划分、多 seed 统计或独立动作评测；当前 smoke 从完整 40 条动作库加载数据，但实际采集只用 walk1/dance1，不能据此声称泛化。
- 尚未通过长时检查确定 solver 警告对转移标签、模型误差和训练稳定性的影响。
- 网络激活、特征编码、部分终止头细节、回报采样器和 critic 额外输入等属于论文未完全规定的工程选择；不是作者代码逐指令复现。
